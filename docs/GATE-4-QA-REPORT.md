## Final deliverable (§44)

1. **Architecture.** Offline single-page application with no dependencies. The engine (pure functions) sits behind application services, which sit behind a storage adapter (IndexedDB, or memory as a fallback) and the DOM UI. The build produces one HTML file plus a Windows launcher; the legacy v1 file is the rollback.
2. **Data model.** IndexedDB `coldload` schema v2 with 14 stores: meta, users, sessions, companies, customers, projects, revisions, templates, climate, references, attachments, settings, safetyBackups, auditLog. Details in `GATE-2-DATA-MODEL.md`. The engine input dataset is the v1 format plus optional Gate 3 fields (version 1.1).
3. **Calculation engine.** Version 1.1.0 implements the Stoecker / Dossat / ASHRAE component method:
   - transmission;
   - product (Siebel, with optional entered properties), packaging and respiration (stored and incoming);
   - infiltration (Gosney–Olama, or the air-change method);
   - ventilation air, people, lighting, forklifts and equipment, fans (never negative), defrost;
   - safety factor and run time, with optional pull-down-rate basis and optional no heat-loss credit;
   - machinery-room ventilation for 6 code bases.

   The engine is hash-locked and checked against an independent implementation.
4. **UI/UX.** Login, dashboard, Document Center, customers, three-step project workspace, standards library, settings and help; light and dark themes; responsive down to 390 px.
5. **Standards / references.** Classified register. IIAR 2-2008A clauses are verified from the supplied IIAR tool; ASHRAE, Stoecker, Dossat, IIAR 9, ASHRAE 15, EN 378 and ISO 5149 are listed with edition "to be verified". Tips and report sections link to the register.
6. **Backup / restore.** Checksummed JSON (full, selected or project). Files are validated before writing, a safety backup is taken automatically, and restore can merge, add as copies or replace. v1 files are imported through migration.
7. **Export.** PDF (browser print), XLSX (built in), CSV, project package, v1 JSON. Files open through Windows file associations.
8. **Security model.** Local accounts with PBKDF2 hashing, no default password, expiring sessions and an admin role. Access control only: stored data is not encrypted. Imports are validated and never executed.
9. **QA/QC results.** 70/70 automated tests, 17/17 independent benchmarks, 23/23 regression results identical, 39/39 end-to-end checks.
10. **Known limitations.**
    - Sites and systems are not separate records.
    - No separate "Miscellaneous" load line.
    - Reports are not stored as files.
    - No DOCX export.
    - English only.
    - Data lives in the Edge/Chrome profile, and clearing browser data deletes it (backups are required). No choice of storage folder. No encryption at rest.
    - No large-attachment load test; bulk project creation is slow.
    - Undo does not cover project-information fields.
    - The report contents page has no page numbers.
    - ASHRAE climate values are not included (licensed).
    - One database per PC; projects are shared via project packages.
11. **Recommended future enhancements.**
    - A Windows desktop build (e.g. Electron) for a real data folder, native Open/Save and "open with".
    - Optional encryption at rest.
    - A shared team server for multi-user work.
    - DOCX report.
    - Site and system entities.
    - A miscellaneous-load line.
    - Stored report snapshots per revision.
    - A licensed climate-data import.
    - Translations.
    - Blast-freezer / tunnel freezing-time calculation (the "Freezing of goods" sheet of your workbook).
